# 无设计稿的设计决策

仅适用于全新项目，或没有设计稿、也没有可沿用的项目视觉语言的新界面，或用户明确要求做视觉设计。已有项目的 UI 样式以项目现状为准，本文件不作为改造或对齐依据；有设计稿时以 [设计稿还原](ui-restoration.md) 为准。本文件思路改编自 Anthropic 的 [frontend-design skill](https://github.com/anthropics/claude-code/blob/main/plugins/frontend-design/skills/frontend-design/SKILL.md)，并按本规范的核实与确认要求调整。

## 立场

像一位以“每个客户都有独特视觉身份”著称的设计负责人那样工作：对调色、字体、布局做有主张的选择，这些选择要能从这个产品的主题推导出来，而不是任何项目都能套用的默认模板。用户没有要求“安全”，而是要求“对”。

## 先扎根主题

需求未说明产品是什么时，先自己判断并向用户确认：一个具体的产品主题、它的受众、这个界面的首要任务。行业、题材、材质与行话是独特视觉选择的来源：面向财务分析师的看板与面向儿童的玩具页面不应长得一样。用真实内容与业务词汇贯穿设计，不用 Lorem 占位。

## 设计原则

- 首屏放这个产品世界里最有代表性的东西，以最合适的形式：标题、图像、数据、交互或演示。“大数字 + 小标签 + 渐变装饰”是默认套路，只有确实最合适时才用。
- 字体承载页面性格。一到两个字族即可，两个时必须明显区分；字号、字重、字距与行高形成清晰的比例体系。正文每行不超过约 80 字符（中文约 35–40 字），衬线体行高略大于无衬线体。
- 避免这些最常见的生成痕迹：只给标题中的一个词换色 / 斜体；标签全部大写；在内容上方加不必要的分类小标题。
- 视觉结构即信息。边框、编号、分隔线、眉题、标签必须编码真实的内容关系；只有内容确实是顺序时才用 01 / 02 / 03 编号。
- 非用户触发的动效克制使用：一次编排好的页面进入或一次揭示比到处飞入更有效；每个区块都淡入上滑、每张卡片都有 hover 过渡是模板痕迹。响应用户操作（展开、确认、打开）的动效是欢迎的。
- 文案是设计内容而非装饰：用用户能理解的名字命名事物；主动语态；按钮写清将发生什么（“保存修改”而非“提交”），同一动作全流程同名；错误说明发生了什么与如何修复，不道歉、不含糊；空状态是行动邀请。

## 模板化特征校准

以下外观本身都合法，但它们是“默认”而不是“选择”，会在任何主题下反复出现。需求明确指定某种外观时照做；需求留白的维度不要花在这些默认上：

1. 米白背景（约 `#F4F1EA`）+ 高对比衬线大标题 + 陶土 / 暖橙强调色。
2. 近黑背景 + 单一荧光绿或朱红强调色。
3. 报纸式布局：细线、零圆角、密集多栏。
4. SaaS 卡片套件：内容切成同样的圆角卡片，所有层级同一圆角，同一柔和灰阴影，渐变装饰。
5. 模板装饰：每个标题上方的字距拉开的全大写眉题；用“·”串联的元信息；“词 — 片段”式标签；用 `#0B0B0B`、`#111` 代替黑色；小数据标签用等宽字体；链接与按钮文字后追加“→”。

## 两遍流程

**第一遍：设计计划。** 先用文字写出紧凑的 token 体系，再做任何编码：

- 颜色：4–6 个命名基础色，给出 hex；说明每个色的角色。
- 字体：字族及其角色（标题 / 正文 / 数据），字号比例。
- 布局：一句话概念 + ASCII 线框；明确对齐方式（左对齐 / 居中 / 两端）。
- 原则：两三条说明这个页面为什么是它自己。

**对照需求自审。** 把计划逐项和需求比：如果某一项是“同类需求我都会这么做”的默认，而不是为这个主题做出的选择，就改掉它，并说明改了什么、为什么。只有确认计划不是模板后才开始写代码。项目已有 tokens 时，计划必须落在项目 tokens 上，新增 token 需用户确认。

**第二遍：实现与自评。** 按计划编码；注意选择器优先级不要互相抵消（尤其是区块 padding / margin 与元素选择器）。能截图时截图自评；不能时说明未视觉验证。

## 克制与质量底线

- 把大胆用在一处：让一个元素成为被记住的东西，其余保持安静与纪律；删掉不服务于需求的装饰。离开前照一下镜子，摘掉一件饰品。
- 不声张地达到质量底线：响应到移动端、键盘焦点可见、尊重 `prefers-reduced-motion`、对比度达标、调色和谐。
- 所有设计决策仍受代码硬约束：复用项目组件与 tokens、中文注释、500 行、真实字段、字符串 ID。
- 设计计划、自审结论和未验证项写入交付说明；不把“已出设计计划”说成“已完成视觉验证”。
