# 测试、审查与交付

## 选择实际命令

读 package.json；项目有 lint:fix/test:changed 就使用，缺失时运行已有 lint/test/build 或目标文件命令。
不要照搬其它仓库命令。项目无测试框架时优先原生小测试，不为一个小修复安装庞大工具链。
每次写完代码必须运行项目实际配置的 lint / 格式化 / 类型检查（ESLint、Prettier、Biome、Stylelint、oxlint、tsc 或其它，以项目配置文件为准），错误与警告清零；不以 eslint-disable、prettier-ignore 等注释规避，确需禁用说明原因并获用户确认。项目没有配置时说明未运行，不假装通过。

## 行为回归

- bug/行为变更先可重复失败测试，确认失败原因是目标行为，再最小修改使其通过。
- 查询/分页覆盖实际参数、ID 字符串、筛选重置、总数保持、重复事件、失败收尾、旧响应隔离。
- 表单覆盖合法/非法/空值/重复提交/取消；CRUD 分别断言独立入口与 payload。
- 单测 stub API 是允许的测试隔离，生产 mock 必须清理。
- 组件静态骨架、SSR、真实 DOM、后端联调各有边界，不互相冒充。
- 每个测试文件同样 ≤500 行；按场景拆，不删除有效断言来躲红灯。

## 浏览器边界

浏览器验证仅用户明确要求/授权时进行；用户拒绝 Playwright 不换工具规避其意图。
用户后来明确让检查已打开页面时只检查授权页。登录优先现有认证会话；不在提示词/脚本打印密码和 token。
不能安全输入凭据时停止登录，让用户通过受支持的保密机制处理。

只有实际检查入口、交互、分页可见边界、网络请求与控制台后，才报告对应项通过。
设计还原对照用与设计稿相同的视口截图并排比较；无法运行时明确写“仅静态核对”，不以代码读起来正确代替视觉一致。
isolated fixture 页只证明隔离组件，不是用户真实页、真实接口或真实数据。

## 一次合并审查

- 是否满足已确认需求，是否添加未要求的跳转/按钮/默认条件。
- 有设计稿：结构、文案、尺寸间距、颜色字体、状态与响应式是否逐项对照，偏差是否有原因；无设计稿：设计计划是否经过模板化自审。
- 命名、类型、样式 token、可访问性、性能与错误处理是否符合 [代码规范](code-standards.md)；无魔法数、硬编码色值、`!important`、`any`。
- 每条 import/export、每个函数和模块变量、props/emits、模板关键组件中文注释是否准确。
- 字段是否唯一真源、运行时 mock 是否已删除、ID 是否全链路字符串。
- 单文件 ≤500、浮层单独维护、hooks 真实复用、CRUD 入口分离。
- loading/finally、取消、竞态、重复消息、权限、i18n/主题是否沿用项目；uni-app 非长连接请求是否都有 loading。
- 空值：`0` 显示 `0`，null / 空串 / 缺字段文本显示 `-`、组件显示 placeholder；表格、卡片、模块无数据有空状态，且与加载中、失败区分。
- 标签与按钮外观可区分；超出内容有可见滚动条，Tab 页签固定、滚动条在内容区。
- 所有改动属于当前范围，未提交用户改动未被覆盖。

## 完成输出

每次迭代结束都要详细说明并请用户确认，不能只写“已完成”：

改动：逐文件说明改了什么、为什么；新增 / 删除 / 重命名的组件、hooks、接口、依赖单独列出。
影响：涉及的页面、组件、接口、状态、路由、权限、依赖版本；对现有调用方与兼容性的影响。
风险：可能回归的点、未覆盖的场景、依赖未知项的部分、回滚方式。
设计还原：逐维度一致 / 偏差及原因 / 未验证（有设计稿时）。
验证：实际命令、结果、覆盖；lint / 格式化 / 类型检查是否清零。
未验证：原因及所需条件。
待确认：接口/权限/范围冲突与需要用户决定的事项。
不要复述整个过程，不将 lint 或静态标签断言说成页面显示已经修好。
