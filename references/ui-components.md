# UI、组件库与分页

## 选择前核实

先读取 package.json 的依赖与插件配置，再查锁文件、实际安装版本、全局组件 / 插件 / 自定义指令 / hooks 的注册文件和相邻页面的实际用法。
优先级：满足需求的项目业务封装与全局封装 → 项目已引入的第三方组件、插件、指令、hooks 与工具 → 经用户确认的新增实现。相邻页面已经在用的组件与写法，新页面默认沿用，不换成另一种等价实现。
不规定组件库品牌、组件名字或插件品牌；不引入第二套库替代项目现有可用能力。
核实属性、事件、插槽、方法与透传能力，不能用新版本文档猜旧版本行为。
包装层能力不满足时先说明缺口；新增组件、插件或依赖须用户确认。

## 抽屉和表格

- 复杂浮层独立文件，列配置与业务 hook 独立维护。
- 核实包装层最终渲染插槽位置，不能把默认插槽当 footer 或忽视包装组件的额外容器。
- 布局规划标题/来源/筛选/表格/分页所需高度；业务滚动收敛在表格或内容区。
- 子级 100% 高度要求祖先高度明确；flex 链路 min-height:0，固定分页不收缩。
- 不靠 overflow:hidden 隐藏布局问题。无法确定可见性时检查 DOM 边界和 computedStyle，禁止连续猜 CSS。
- 只复用明确要求的交互；普通文本不会因为参考页同位置有链接而自动变成跳转。
- 设计稿与项目组件外观不一致时，不用 CSS 覆盖组件内部结构，列出差异让用户确认，见 [设计稿还原](ui-restoration.md)。

## 分页契约

1. 明确 pageNum/pageSize 和 page.records/total 的实际层级。
2. 核实当前组件的分页模型、受控状态和变更事件，不能混用不同库的参数约定。
3. 使用表格内置分页时按实际安装版本传入配置；使用项目全局分页封装时核实其完整透传。
4. 单个变更入口，忽略同页/同条数事件，加载期间阻止重复查询。
5. 加载期间保留已知 total，防止总页数归零触发自动回退、重复调用。
6. 请求不同查询范围才清总数；翻页失败保留范围及可重试能力。
7. “始终显示”意味着空列表、单页、多页、加载、失败都验证；不得加 total>0 的 v-if 或 hideOnSinglePage:true。
8. 组件存在/SSR HTML 包含页码仅证明渲染，不证明真实视口可见；结论分层报告。

## 封装透传

基于库的包装组件必须透传四类能力：未消费 attrs、事件、class/style、具名与作用域插槽；按需要 expose 表单校验、清空选择或实例方法。
class/style 明确落在哪一层；inheritAttrs:false 时不可忘记转发。Vue 包装组件 template 保持单根节点，否则 attrs 无法自动透传。
封装只加项目默认值与约定，不缩减底层组件能力；缺失的透传视为封装缺陷而非“按需再加”。
纯只读列表不要伪造业务字段来凑表单 schema；必须使用库经核实的合法插槽或组件能力。

## 空值与空状态

| 后端返回 | 文本字段展示 | 表单 / 输入类组件 |
| --- | --- | --- |
| 有值 | 原值 | 原值 |
| `0` | `0` | `0` |
| `null` / 缺字段 / `''` | `-` | 空值（多为 `''`），显示 placeholder；组件文档要求 `undefined` / `null` 才显示 placeholder 时以文档为准 |
| `false` | 按已确认枚举文案 | 原值 |

- 只在展示层用一个具名纯函数处理同字段占位，不在 API 层转换、不改字段名、不跨字段兜底；不能用 `value || '-'`，它会把 `0` 吞成 `-`。
- 表格、卡片列表、详情分区、统计模块、图表等任一页面模块没有数据时，显示项目统一的空状态组件（项目没有时确认样式与文案），不留空白容器。
- 加载中显示 loading，不先闪空状态；加载失败显示错误与重试入口，不显示为“暂无数据”；三种状态互斥。

```js
/** 文本字段展示值：仅 null、undefined、空串显示“-”，0 原样显示。 */
export function formatFieldText(value) {
  if (value === null || value === undefined || value === '') {
    return '-'
  }
  return value
}
```

## 标签与按钮

- 标签（状态、分类、标记）是不可点击的展示元素：用项目的 Tag / Badge 类组件，不用 Button 组件或按钮 class 冒充；无指针手势、无 hover / active / focus 反馈，不绑定点击事件。
- 外观必须与按钮明显区分：尺寸更小、内边距更紧、浅底或描边、无按钮式阴影与按压态；颜色来自项目语义 token。
- 已有项目中标签与按钮外观相同时，指出问题并请用户确认是否调整，不擅自改全局样式。

## 滚动与 Tab

- 超出可视区域的内容必须出现明显可见的滚动条：不使用 `scrollbar-width: none`、`::-webkit-scrollbar { display: none }` 等隐藏手段；项目有滚动条样式 token 时沿用。
- 滚动收敛在内容区：页面外框、标题、筛选、页签、分页固定，只有内容区滚动；滚动容器必须有确定高度（flex 链路 `min-height: 0`，内容区 `flex: 1; overflow-y: auto`）。
- Tab：页签栏固定不随内容滚动（`flex-shrink: 0`），每个 Tab 内容区各自滚动，滚动条出现在内容区域内而不是整页或页签栏外侧；切换 Tab 时按需求决定是否保留各自滚动位置。
- uni-app 用 `scroll-view` 时设置明确高度，并按官方文档核对 `show-scrollbar` 等属性在各端的支持；某端无法显示滚动条时在交付中写明。

## 主题与交互

沿用项目 tokens、语义色、间距、字号和字体；不在非主题任务改全局样式。设计值与项目 token 不一致时列出差异确认，不在组件里写字面值。
核对主题切换、hover/focus/disabled/loading/empty/error。Teleport 仍应能读取根变量。
权限沿用真实后端码，不推测按钮权限或资源 ID；删除/冻结/批量提交有确认与重复操作保护。
i18n 项目同步已有语言与 key 规范；没有 i18n 不擅自引入体系。
金额按项目精度策略处理，不用普通浮点计算猜财务结果；时区必须确认。
